# SSDSim RAID4（3+1）版本

本目录现以 RAID4 控制流程为入口。修复前的文件保存在 `audit_artifacts/before_raid4/`；原 GitHub 版本目录没有修改。

## 布局

| 成员 | 通道 | 用途 |
|---|---|---|
| SSD0 | 0–3 | 数据 |
| SSD1 | 4–7 | 数据 |
| SSD2 | 8–11 | 数据 |
| SSD3 | 12–15 | 固定校验成员 |

每个 SSD 在模型中对应4条channel；仍使用一个 SSDSim 的闪存/GC后端。每条条带含3个数据页和1个校验页。校验在SSD3内的4条通道和2个chip间分布，不轮转到数据SSD。

用户页号从0开始，内部数据LPN从1开始。条带号为 `user_page / 3 + 1`，数据成员为 `user_page % 3`，成员内部通道为 `(stripe_id-1)%4`。这是固定逻辑条带映射，替换了旧版按请求到达顺序拼条带的方式。默认8 KiB页对应每条带24 KiB用户数据。

## 构建和运行

Windows PowerShell，在本目录：

```powershell
.\build.ps1
.\ssd.exe 1 "你的trace文件路径"
```

也可以使用已修正的Makefile：`mingw32-make all`，Linux为`make`。不再强制32位，不依赖不存在的`insert_to_buffer.c`或指定版本的`gcc-11`。主程序也可直接用GCC构建：

```powershell
gcc -std=gnu99 -O2 -g -D_FILE_OFFSET_BITS=64 -D__USE_MINGW_ANSI_STDIO=1 ssd.c flash.c pagemap.c hash.c initialize.c raid4.c -lm -o ssd.exe
```

运行时从**当前工作目录**读取 `page.parameters`，并写入输出。因此使用其他目录存放实验结果时，需要把参数文件复制到该目录，再调用程序的绝对路径。

参数1是trace轮数，参数2是trace文件。trace每行至少5列：`time_ns device lsn sector_count operation`，其中读=1、写=0；可有第6列，但当前不按其调度。时间戳须非递减。空文件、无末尾换行均支持，非法行直接报错退出。主程序不再越过缺失的argv参数。

当前配置约束是16条channel、每通道2个chip、32个chip合计、`allocation=0`、`dynamic_allocation=2`、`advanced command=0`、每页1–32个sector。fast GC与data reorganization保持原参数，默认均关闭；本轮验收覆盖的是默认GC路径。

## 校验缓存与调度

- 按条带串行化读写，避免覆盖写读取到尚未完成的旧版本；不同条带仍可以利用不同通道/chip并行。
- 覆盖写先读取旧数据；校验缓存未命中时读取该条带的旧校验。读取完成后才排入单控制器的XOR计算，计算完成后再编程数据。
- 校验更新驻留在LRU缓存中。默认DRAM容量按可容纳的校验页数量折算；缓存中正在处理的条带被固定，不能提前淘汰。旧数据整页只读取一次，以同时满足校验增量计算和NAND异地编程的保留扇区需求。
- 数据编程完成、最新校验进入DRAM后可完成主机写请求。这是写回校验缓存语义；不模拟掉电丢失缓存。
- 淘汰时保留缓存项直到校验编程完成；DRAM不足一页时按无缓存处理，使用一页控制器临时空间并立即写回。
- 每轮EOF都会完成前台请求，刷新全部脏校验，完成后台I/O与GC；独立条带的末尾校验刷新可并行。不完整条带也有校验，其未写入位置在模型中视为零。
- 校验位置与有效扇区状态存入每条带的独立元数据。校验标记只用于区分请求类型，不再作为普通数据映射表下标。

旧 `ssd.c` 中的缓存/请求辅助函数保留用于对照；当前可执行程序由 `raid4.c` 驱动，不走旧的RAID5缓存及trace结束流程。新增控制流程明确替换旧的按访问频次重排缓存策略，使用标准LRU；因此不能把修复前后的性能差异全部解释为RAID等级变化。

## 可选单成员故障重建

第三个运行参数指定故障成员，编号0–3：

```powershell
.\ssd.exe 1 "你的trace文件路径" 0
.\ssd.exe 1 "你的trace文件路径" 3
```

前者测试SSD0数据重建，后者测试SSD3校验重建。未提供此参数时只执行正常态仿真。

故障发生在trace结束、脏缓存及后台I/O排空之后。程序将该成员的物理页重置为空白替换成员，读取其他成员中的条带数据/校验，等待XOR计算后写入替换成员，并重新校验映射。数据成员故障从另外两个数据成员及校验成员重建；校验成员故障从三个数据成员重建。

本功能模拟**正常状态排空后的单成员离线重建**，不包含故障过程中继续服务主机I/O、多成员故障或带未持久化缓存的掉电恢复。和原SSDSim一样，模型不保存真实用户字节；验证对象是映射、有效扇区、读取/计算/写入顺序及耗时，不能等同于字节级校验和验证。

## 输出

- `ex.out`：每个主机请求一行，依次是到达时间、LSN、大小、操作、开始时间、完成时间、延迟（ns）。开始时间按到达时间记，包含等待。
- `raid4.stats`：新的key=value统计；同步写入 `statistic10.dat`。包含提交/完成数量、主机扇区数、预处理页数、缓存命中/淘汰、XOR数量、GC、各通道的数据/校验写入次数及重建结果。
- `normal_end_ns`包含本轮正常请求及最终刷新；`recovery_elapsed_ns`单独记录可选重建时间。主机平均延迟包含排队时间。启用重建时，物理读写/XOR总计数包含重建开销，主机请求计数不包含重建。
- `mapping_check=PASS`：结束时数据正反向映射、固定校验成员、校验有效位、空闲页计数及请求/缓存/GC收尾均通过检查；不代表已验证真实字节内容。

需要逐个NAND请求日志时可设置：

```powershell
$env:RAID4_TRACE_EVENTS = "1"
.\ssd.exe 1 "你的trace文件路径"
Remove-Item Env:RAID4_TRACE_EVENTS
```

此时额外输出 `raid4.events`，每行是：时间、条带号、READ/WRITE、内部LPN、十六进制有效位图、channel。默认不生成该大日志。

`aged=1`时，初始已占用页数以`aged ratio`为目标，不再无条件填充到80%；预处理已存在的有效页计入已占用页。它是初始占用目标，不是严格的“无效页占总页比例”。修改参数比较实验时应统一此口径。

## 验证与文件说明

```powershell
python tests\test_raid4.py
```

测试自动编译整个程序，使用完整NAND/GC后端，结果保存在 `audit_artifacts/raid4_tests/results.json`。23项回归全部通过：部分页/跨页写、精确读取与EOF、CPU计算排队、同条带顺序、单页/零缓存、多轮trace、4个成员重建、带老化混合负载、持续GC、32-sector有效位、256页/block、空trace、无换行、容量环绕、GC后数据成员重建、非法输入及缺失参数。

5000次覆盖写的GC压力场景实际触发787次擦除和41次有效页搬迁；32-sector场景还覆盖GC及校验成员重建。另用未缩小的原 `page.parameters`（8,388,608物理页）完成一次读写烟测。

主要文件：

- `raid4.c/h`：固定成员映射、条带请求队列、校验缓存、事件调度、收尾、重建和最终一致性检查。
- `flash.c`：校验读取选址和有效位、固定成员分配、按chip选写请求、读队列尾指针修复。
- `pagemap.c`：独立校验映射、预处理参数、GC迁移映射及空闲页计数修复。
- `initialize.c/h`、`hash.c`：类型定义、TLC计数及空Hash释放等修复。
- `audit_artifacts/RAID代码对比与正确性审计.md`：修复前的历史审计，不是当前版本的验收结论；旧的抽取函数脚本也针对修复前代码，请以新tests为回归入口。

这些测试证明所覆盖的边界与状态机行为；尚未进行长期真实工作负载的性能标定，也未验收高级闪存命令、fast GC及data reorganization的全部组合。
